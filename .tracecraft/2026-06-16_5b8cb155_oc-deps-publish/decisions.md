# Decisions

## Decision: コミット分割単位

### 背景
Initial commit 以降の大量の変更を一括 push する前に、適切な粒度でコミットを分ける必要があった。

### 選択肢
1. 全変更を1コミット
2. ファイル種別ごとに分割（5コミット）
3. 機能ごとにさらに細かく分割

### 採用した案
ファイル種別・性質ごとに5コミットに分割。

### 採用理由
変更の性質が明確に異なる（構成整理、依存更新、機能実装、開発環境、ドキュメント）ため、レビュー時に各コミットの意図が一目でわかる。

### 採用しなかった案と理由
- 1コミット: 変更が大きすぎてレビュー不可能
- さらに細分化: src/main.rs の変更は相互依存が強く、機能単位での分割は困難

## Decision: .kube/ を .gitignore に追加

### 背景
リポジトリ内に .kube/config（kubeconfig）が存在していた。

### 採用理由
kubeconfig には認証情報が含まれるため、公開リポジトリに含めてはならない。
